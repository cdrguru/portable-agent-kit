# Iterative Rapid Development Protocol

> **Prompt Origin:** Template from Portable Agent Collaboration Kit (PACK)
> **Interpretation Confidence:** High
> **Clarification Recommended:** No

**Usage:** Copy this template into your orchestrating agent session to run parallel development batches.

---

## Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `${ProjectName}` | Name of the project being developed | `my-saas-app` |
| `${BatchSize}` | Number of parallel tasks per batch | `5` |
| `${TestCommand}` | Command to run tests | `npm test`, `pytest`, `make test` |
| `${TaskPriority}` | Priority order for task selection | `Bugs > Security > Refactors > Features` |

---

## 🚀 Rapid Application Development Mode

**Context:** Human-in-the-loop parallel development using the **Portable Agent Collaboration Kit (PACK)**.

**Goal:** Rapidly develop `${ProjectName}` by iterating through batches of `${BatchSize}` disjoint tasks executed by parallel cloud agents.

---

### ♻️ The Cycle

You (Orchestrator Agent) guide the human through these 4 steps repeatedly:

#### Step 1: Generate (The Scanner)

Analyze the codebase for the next `${BatchSize}` highest-priority disjoint tasks.

**Priority order:** `${TaskPriority}`

**Constraints:**
- Tasks MUST be disjoint (modify different files/modules)
- Each task should be completable in a single agent session
- Tasks should have clear acceptance criteria

**Output:**
- Populate `cloud_tasks/` with:
  - `manifest.json` — batch metadata and task summaries
  - `task_1.md` through `task_${BatchSize}.md` — individual task prompts

**Pre-check:** If `cloud_tasks/` is not empty, prompt to Archive first (Step 4).

#### Step 2: Execute (The Cloud)

Instruct the human to spawn `${BatchSize}` parallel cloud agent sessions.

**Instructions to give:**
```
Open ${BatchSize} cloud agent sessions (e.g., claude.ai tabs).
Paste the contents of cloud_tasks/task_N.md into Session N.
Each session should create a PR when complete.
```

**Wait** for human confirmation that all sessions have created PRs.

#### Step 3: Merge (The Reviewer)

Review and merge each PR systematically.

**For each PR:**
1. Pull the branch locally
2. Run tests: `${TestCommand}`
3. If tests pass → Squash & Merge
4. If tests fail → Attempt trivial fix OR revert

**Goal:** Maintain a green main branch at all times.

**Log outcomes** in `manifest.json`:
```json
{
  "task_1": {"status": "merged", "pr": "#42"},
  "task_2": {"status": "reverted", "reason": "test failure in auth.test.js"}
}
```

#### Step 4: Archive & Repeat

Preserve batch history and prepare for next iteration.

**Actions:**
1. Create archive folder: `.artifacts/batches/YYYY-MM-DD_Batch_N/`
2. Move all `cloud_tasks/*` files into archive folder
3. Clear `cloud_tasks/` directory
4. Update `.artifacts/batches/index.md` with batch summary

**Loop:** Ask "Ready to scan for the next batch?"

---

### 🚦 State Machine

When starting or resuming, check current state:

```
┌─────────────────────────────────────────────────────┐
│                  Check cloud_tasks/                  │
└─────────────────────────────────────────────────────┘
                          │
            ┌─────────────┴─────────────┐
            ▼                           ▼
       [Empty]                    [Populated]
            │                           │
            ▼                           ▼
   Start Step 1              Ask: "Where are we?"
     (Generate)                - Execute (Step 2)?
                               - Merge (Step 3)?
                               - Archive (Step 4)?
```

**Recovery prompts:**
- "I see tasks in `cloud_tasks/`. Have the cloud agents finished creating PRs?"
- "Are there open PRs ready for review?"
- "Should we archive the current batch and start fresh?"

### 📋 Task Prompt Template

Each `task_N.md` should follow this structure:

```markdown
# Task N: [Brief Title]

> **Prompt Origin:** Generated by Orchestrator Agent
> **Batch:** YYYY-MM-DD Batch N
> **Isolation:** This task modifies only: [list files/modules]

## Goal
[One sentence describing what to accomplish]

## Context
[Relevant background, constraints, dependencies]

## Acceptance Criteria
- [ ] [Specific, testable criterion]
- [ ] [Another criterion]
- [ ] Tests pass: `${TestCommand}`

## Files to Modify
- `path/to/file1.ts`
- `path/to/file2.ts`

## Out of Scope
- Do NOT modify [other files]
- Do NOT change [unrelated functionality]

## Deliverable
Create a PR with:
- Descriptive title: "feat: [brief description]"
- Link back to this task in PR description
```

---

### 🛡️ Guardrails

**Before generating tasks:**
- Ensure main branch is green
- Pull latest changes
- Verify no conflicting PRs are open

**Task isolation rules:**
- No two tasks in a batch may modify the same file
- Shared dependencies (package.json, requirements.txt) should be handled in dedicated tasks
- Database migrations should be single-task batches

**Merge conflict prevention:**
- If conflict detected, pause batch and resolve before continuing
- Consider reducing `${BatchSize}` if conflicts are frequent
